# Security boundaries

- Admin authentication belongs to Cloudflare Access. Every admin request also validates the signed Access JWT and exact owner email server-side. Missing configuration is denied. No local password/session implementation or production test-auth bypass exists.
- Two deployments separate public portfolio reads and the contact-only POST endpoint from authenticated portfolio writes. Entire admin Worker protection avoids partial-path Access mistakes. Admin origin must match configured HTTPS hostname.
- State-changing browser requests require same-origin `Origin` and a custom request header; cross-origin admin preflight is refused. Access session cookies are managed by Cloudflare. Public CORS never allows credentials.
- D1 SQL uses bound parameters. Only fixed, server-chosen column names occur in dynamically assembled SQL. Revisions prevent stale edits/uploads/deletes overwriting newer changes.
- R2 remains private. Asset keys are generated by the server and recorded in D1. Media routes accept UUID asset IDs, not object paths. Public media requires an active published project referencing that asset. Unpublishing denies subsequent requests; previously downloaded media and requests already in progress cannot be revoked.
- Uploads use a bounded stream reader, signature/structure checks and dimension checks, safe content types, and generated names. Audio: 30 MiB. Artwork: 5 MiB. HTML/SVG/executable uploads are refused. No uploaded file is executed or interpolated as HTML.
- Total reserved/live/garbage assets count toward the 1 GiB quota. Reservation happens in one atomic INSERT/SELECT to avoid simultaneous oversubscription. The 100-project cap limits metadata/list workloads.
- Asset reservations track files before R2 writes. Failed or replaced assets remain tracked until deletion succeeds. Soft deletion immediately removes public access. Hourly cleanup retries failures; stale pending entries have a one-hour grace period. In-flight uploads cannot make a deleted project public again.
- Internal errors return generic text without tokens, object keys or stack traces. Logs contain only generic request/cleanup failure notices. Private data/secrets are not cached. CSP and other security headers protect the Worker responses. Public GitHub Pages HTML carries an early CSP meta tag; response headers still depend on the host.
- No account tokens, API keys, authentication JWTs or private email credentials appear in frontend configuration. The Access audience/team name and deployed URLs are identifiers, not secrets. `ADMIN_EMAIL` is configured with Wrangler secret management. Local secrets are ignored by Git.

Tests are documented in DEPLOYMENT.md. Hosting configuration, Access policy, browser playback, real media formats and CPU under Cloudflare Free still require deployment verification. Signature checking is not malware scanning or a full media decoder. Application quotas do not cap R2 request billing, unrelated bucket objects or account-wide usage. No SOC certification or guarantee of complete security is claimed.

## Contact endpoint

- `/api/contact` exists only in public mode. It requires an explicitly allowed HTTPS Origin; preflight permits only POST and Content-Type. No cookies or browser credentials are needed. Origin checks are not authentication and cannot stop non-browser clients on their own.
- Turnstile Siteverify must return success with the request origin's exact hostname and action `contact`. Invalid, expired, reused, malformed and unverifiable tokens do not send email. There is no production verification bypass.
- The body is bounded to 24 KiB; messages to 5,000 UTF-16 code units, names to 100, addresses to 254. Fields and service choices are allowlisted. Optional tracks per mix must be an integer from 1 to 60. Addresses are single ordinary mailboxes; CR/LF and control characters cannot reach headers. The email body is plain text only. No attachments or arbitrary headers are accepted.
- Sender and subject are server-controlled. Only the validated visitor email becomes Reply-To (`reply_to`). The single recipient comes only from `CONTACT_RECIPIENT`, a Worker secret, and is independently validated as a single mailbox. Client recipient/sender/header fields are rejected. No automatic reply to the visitor is sent. Resend does not provide the old Cloudflare binding's recipient restriction: this application enforces the fixed recipient. Use a sending-only Resend key restricted to `asmixes.com`; protect it because a stolen key could send outside the application.
- `RESEND_API_KEY`, `CONTACT_RECIPIENT`, `TURNSTILE_SECRET` and `CONTACT_RATE_SECRET` belong in Worker secrets. The public Turnstile site key is safe in frontend configuration. Neither credentials nor private recipient addresses belong in Git, Pages, HTTP responses, or application logs. The old `wrangler.contact.local.jsonc` remains ignored to protect any pre-existing private configuration, but is no longer used or generated.
- D1 fixed-window counters reserve atomically: five attempts/IP/10 minutes and 100 verified send attempts/UTC day by default. IP identifiers use secret-keyed HMAC with daily rotation; raw IPs and submitted messages are not stored. Invalid inputs count toward the IP limit; provider failures count toward the global cap. A missing trusted Cloudflare IP, database, required secret, or valid configured recipient fails closed. Shared networks can hit the same IP limit, and window boundaries permit bursts.
- Counter keys include their time window. Expired windows cannot block later submissions. An expiry index supports bounded batches of 500 deletions on the hourly public-Worker cron; large backlogs clear over repeated batches. Pseudonymous IP identifiers remain sensitive data; cleanup limits retention but an outage may delay physical deletion. No counters or submissions are logged. Edge rate-limit bindings also use the trusted IP as a transient key inside Cloudflare; it is not written to D1 or application logs.
- Resend is called only at the fixed HTTPS `/emails` endpoint, with redirects refused and an eight-second timeout. API errors (including pending-domain rejection, quota exhaustion and authorization failure), malformed responses, network failures and missing acceptance IDs return generic errors, never provider response bodies. No automatic email retries occur. Provider errors and verification failures never report success. The UI retains fields on failure and refreshes verification for retries. Acceptance is not a guarantee of inbox placement. A dropped HTTP response can leave delivery status uncertain; there is no exactly-once delivery guarantee and a retry can duplicate an email. Rate limits are not a complete network-level DoS or account-cost guarantee.

## Public resource protection and frontend CSP

- Public POST contact requests pass edge per-IP and per-location aggregate bindings before body reading, D1 or outbound calls. GET/HEAD portfolio and media requests pass independent read bindings before D1/R2. Missing trusted IP, missing bindings and binding errors fail closed. OPTIONS performs only origin/method validation, without database/storage access.
- Edge limits add no D1 writes. Durable contact counters remain to enforce the stricter ten-minute and daily email budgets across locations. Request handling never runs counter cleanup; the existing hourly cron removes at most 500 expired rows per invocation. A sustained backlog may require separately approved operational cleanup or a revised cron batch budget.
- Media GET uses the immutable uploaded size recorded in D1 and one R2 get. HEAD checks object existence with one R2 head. Publication is still rechecked in D1 on every request; no cache can bypass unpublication. Range requests are subject to the generous read budget, without special exemptions attackers could exploit.
- The public page permits local scripts/styles, the exact API origin for connections/artwork/audio, and challenges.cloudflare.com for Turnstile scripts/frames. No inline script/style or eval permissions are granted. Canvas animation and CSS animations need no extra CSP source. The public admin-link page uses a separate local-assets-only policy.
- Meta CSP is included in the actual GitHub Pages artifact and fallback copy, before assets. It cannot implement frame-ancestors, report-only or HTTP response headers; header-level clickjacking protection needs a separately approved proxy/host change. Turnstile pre-clearance is not used by this frontend; enabling it would additionally require connect-src self. Keep the exact API origin in CSP synchronized with portfolio-config.js; tests detect divergence.
