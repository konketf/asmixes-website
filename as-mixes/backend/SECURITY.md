# Security boundaries

- Admin authentication belongs to Cloudflare Access. Every admin request also validates the signed Access JWT and exact owner email server-side. Missing configuration is denied. No local password/session implementation or production test-auth bypass exists.
- Two deployments separate read-only public routes from authenticated writes. Entire admin Worker protection avoids partial-path Access mistakes. Admin origin must match configured HTTPS hostname.
- State-changing browser requests require same-origin `Origin` and a custom request header; cross-origin admin preflight is refused. Access session cookies are managed by Cloudflare. Public CORS never allows credentials.
- D1 SQL uses bound parameters. Only fixed, server-chosen column names occur in dynamically assembled SQL. Revisions prevent stale edits/uploads/deletes overwriting newer changes.
- R2 remains private. Asset keys are generated by the server and recorded in D1. Media routes accept UUID asset IDs, not object paths. Public media requires an active published project referencing that asset. Unpublishing denies subsequent requests; previously downloaded media and requests already in progress cannot be revoked.
- Uploads use a bounded stream reader, signature/structure checks and dimension checks, safe content types, and generated names. Audio: 30 MiB. Artwork: 5 MiB. HTML/SVG/executable uploads are refused. No uploaded file is executed or interpolated as HTML.
- Total reserved/live/garbage assets count toward the 1 GiB quota. Reservation happens in one atomic INSERT/SELECT to avoid simultaneous oversubscription. The 100-project cap limits metadata/list workloads.
- Asset reservations track files before R2 writes. Failed or replaced assets remain tracked until deletion succeeds. Soft deletion immediately removes public access. Hourly cleanup retries failures; stale pending entries have a one-hour grace period. In-flight uploads cannot make a deleted project public again.
- Internal errors return generic text without tokens, object keys or stack traces. Logs contain only generic request/cleanup failure notices. Private data/secrets are not cached. CSP and other security headers protect the Worker responses; GitHub Pages headers depend on GitHub and are not controlled by this Worker.
- No account tokens, API keys, authentication JWTs or private email credentials appear in frontend configuration. The Access audience/team name and deployed URLs are identifiers, not secrets. `ADMIN_EMAIL` is configured with Wrangler secret management. Local secrets are ignored by Git.

Tests are documented in DEPLOYMENT.md. Hosting configuration, Access policy, browser playback, real media formats and CPU under Cloudflare Free still require deployment verification. Signature checking is not malware scanning or a full media decoder. Application quotas do not cap R2 request billing, unrelated bucket objects or account-wide usage. No SOC certification or guarantee of complete security is claimed.
